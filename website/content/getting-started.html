Make it yours.

Create a profile for your identity and hardware before asking Nix to change your system.

1. Prepare your environment

On macOS, install Nix using the Determinate Nix Installer and review its installation options. On NixOS, use your existing Nix installation. Ensure the nix-command and flakes experimental features are enabled. You also need Git.

Fork the repository, then clone your fork. Replace YOUR-USERNAME below.

git clone https://github.com/YOUR-USERNAME/nix-multi.git
cd nix-multi
cp profiles/example.nix profiles/local.nix

2. Set your identity and hardware

Edit profiles/local.nix: set your user name, email, time zone, locale, and any host preferences. Keep gpuConfig empty until you have reviewed GPU passthrough for your hardware.

For each NixOS target, generate fresh hardware configuration on that target:

sudo nixos-generate-config --show-hardware-config

Save the output in your own hardware module, for example profiles/local/hardware/nixos-desktop.nix. Update the profile's hardwareModules paths. Review disk UUIDs, file systems, boot loader, firmware, and networking. macOS does not use the NixOS hardware module.

The local profile paths are ignored by Git.

Nix flakes normally see only tracked files in a Git checkout. After reviewing your local profile and hardware modules, explicitly track the files you need with git add -f, or choose a different tracked profile name. Never add private keys or plaintext secrets.

3. Connect the profile to your host

In flake.nix, change the profile import to your own file. Define an output name for your host and point it at the appropriate reusable machine configuration. For example, this Darwin output uses the existing macOS machine module:

darwinConfigurations."my-mac" = mkSystem {
  name = "my-mac";
  machine = "macbook-pro";
  system = "aarch64-darwin";
  inherit user;
  isDarwin = true;
};

For NixOS, use machine = "nixos-desktop";, your own output and host name, system = "x86_64-linux";, and hardwareModule = profile.hardwareModules.desktop;. Set desktopManager to "end4", "omarchy", or "plasma". See the architecture guide for the composition model.

4. Replace secret recipients

Base your root secrets.nix on secrets.nix.example. Add your own public recipient keys and create new encrypted files for enabled secret declarations. Existing encrypted secrets cannot be decrypted by your fork. Adapt secret module paths and identities, and omit maintainer-specific SSH modules.

Follow the Agenix guide alongside the relevant platform modules. Keep private keys outside Git and the Nix store.

5. Evaluate and build

Review the modules imported for your host, track your new configuration files, then evaluate:

nix flake check

# macOS example: build without switching the active system
nix build '.#darwinConfigurations.my-mac.system' --no-link

# NixOS example: replace my-desktop with your output name
nix build '.#nixosConfigurations.my-desktop.config.system.build.toplevel' --no-link

Run the build for your platform. A cross-platform flake may need a suitable remote builder for builds targeting a different operating system.

6. Apply your chosen host

Only after reviewing a successful build, run the matching activation target with your output name:

# macOS
CONFIRM_APPLY=1 make setup-macos MACOS_CONFIG=my-mac

# NixOS desktop
CONFIRM_APPLY=1 make setup-linux LINUX_CONFIG=my-desktop

Activation installs packages and changes system settings. The explicit confirmation is required by the repository's setup commands. Keep a known working generation available while trying changes.
