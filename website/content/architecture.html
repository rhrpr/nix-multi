The configuration separates reusable behavior from personal values and hardware details.

How a host comes together

flake.nix
  ├── inputs + locked dependency revisions
  ├── profile → user, preferences, hardware paths
  └── host output → lib/mksystem.nix
        ├── machines/ → platform composition
        ├── modules/ → system and host features
        └── home/ → Home Manager configuration

flake.nix selects the profile and defines each output. lib/mksystem.nix passes the platform, identity, hardware, and desktop settings to system and Home Manager modules.

Where changes belong

LocationResponsibility
profiles/User identity, locale, host preferences, hardware modules, and personal imports.
machines/Compose modules for macOS, a NixOS desktop, or a NixOS guest.
modules/darwin/macOS apps, system settings, users, and optional tooling.
modules/nixos/NixOS system, desktop, applications, and services.
modules/hosts/Host capabilities such as VM management and GPU passthrough.
modules/vm/Guest system configuration and VM integration.
home/Shared packages, shell configuration, editors, and platform adaptations.
devshells/Focused development environments selected through flake outputs.

Output names and machine modules

An output is the name you select after # in a flake reference. In mkSystem, name supplies the host name, while machine chooses a module from machines/. Set machine explicitly when your host name differs from an existing module name.

Keep personal values in your profile

Start from profiles/example.nix. Replace user and hardware settings in your own profile instead of embedding personal values into shared modules. Review all imported modules: a profile is an organizing boundary, not a guarantee that every upstream default fits your machine.

Home Manager follows the platform

home/default.nix imports the shared core and shell setup, then platform-specific modules and your additional Home Manager modules. Desktop-specific conditions determine which configuration files are managed. Omarchy, for example, owns parts of its live desktop theming.

Enable host capabilities deliberately

Virtualization, passthrough, desktop environments, and local AI services have different requirements. Read their module options and hardware assumptions before enabling them. Keep the reusable foundation small enough to understand.
