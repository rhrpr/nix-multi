03 / CHOOSE

Choose your environment.

Share a foundation across machines while keeping the platform-specific parts explicit.

macOS on Apple Silicon

The maintained Darwin configuration targets aarch64-darwin. It combines nix-darwin system settings, Home Manager, application management, Aerospace, and optional development and AI tools.

Use your own Darwin output and profile. Review macOS application and service modules before switching. For an ARM64 Linux guest, start with the UTM workflow below.

NixOS desktops

The maintained desktop outputs target x86_64-linux. Choose end4 Hyprland, Omarchy, or KDE Plasma 6. Each named output enables its own desktop and Home Manager configuration. Supply hardware configuration generated on the machine you intend to use.

Maintainer outputMeaning
nixos-end4end4 Hyprland desktop.
nixos-omarchyOmarchy desktop.
nixos-plasmaKDE Plasma 6, SDDM, and Plasma Home Manager settings.
vm
nixos-vm-omarchy		Omarchy NixOS guest.
nixos-vm-hyprlandend4 guest compatibility profile.

The Makefile selects LINUX_CONFIG ?= nixos-end4, with all three choices commented on the same line. Override it with LINUX_CONFIG=nixos-omarchy or LINUX_CONFIG=nixos-plasma. The nixos-desktop alias selects Omarchy; the older nixos-desktop-end4 and nixos-desktop-omarchy aliases remain available. All desktop choices share the same host name and hardware profile.

These are examples for the maintainer's machines. Create your own output names and hardware paths before activation.

Virtual machines

Align the guest hardware and architecture first.

The VM outputs declare x86_64, but the current maintainer VM hardware module selects ARM64. Omarchy requires x86_64, so these defaults currently fail full flake evaluation. Generate hardware configuration for your intended guest and use a compatible desktop before deployment.

Apple Silicon and UTM

The UTM workflow starts with an ARM64 NixOS ISO, followed by guest installation and configuration over SSH. Download the ISO without changing the host system:

make vm-download

Create the guest in UTM, select resources appropriate to your machine, install NixOS, and set up your own guest account and SSH access. Review scripts/vm-setup.sh and set VM_SSH_USER, VM_SSH_HOST, and VM_SSH_PORT for that guest before deployment.

QEMU and Linux hosts

Use the helpers to inspect the configuration for your target architecture:

./scripts/qemu-config.sh config
./scripts/qemu-config.sh test x86_64

Native guest and host architectures are the route to hardware acceleration. Building or emulating another architecture has different requirements; a cross-platform helper does not guarantee accelerated execution. The current main flake's maintained guest outputs are x86_64 Linux; ARM64 UTM installation is a separate workflow.

GPU passthrough is optional

The repository includes hardware-specific passthrough tooling. Adapt PCI addresses, device IDs, IOMMU groups, and driver configuration to your own GPU. Do not assume the maintainer's RTX 3080 values apply, or that a consumer GPU supports simultaneous host and guest use in every mode.

Read the passthrough module and the detailed VM guide before changing device ownership.
