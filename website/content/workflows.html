04 / USE IT

A repeatable daily workflow.

Make an intentional change, check the result, and apply it to the host you selected.

Start with inspection

make help       # List available targets
make check      # Run flake checks
make fmt        # Format Nix files

make fmt edits files. Review the diff before committing. Flake checks evaluate configuration and the configured checks; they do not prove that a particular disk layout or GPU setup is correct for your hardware.

Enter a development shell

Choose a shell for the project you're working on. These commands enter development environments without switching the active system configuration.

CommandEnvironment
make devDefault tooling and formatting.
make dev-flutterFlutter and Android development.
make dev-webWeb development.
make dev-pythonPython development.
make dev-rustRust development.

You can also select an output directly, such as nix develop .#web.

Update with a reviewable diff

nix flake update
git diff -- flake.lock
nix flake check

Updating the lock file changes pinned dependencies. Build your selected host afterward, review any changed options, and activate only when you are ready. Commit a working configuration so you have a clear reference for the next change.

Manage secrets with Agenix

Declare recipients in your own secrets.nix and map encrypted files into the relevant secret modules. To edit a new secret, after creating its recipient entry:

nix run github:ryantm/agenix -- -e secrets/my-secret.age

Encrypted .age files can be tracked. Private identity keys, OAuth tokens, and decrypted files stay outside the repository. Confirm ownership, permissions, and destination paths in the Darwin or NixOS module. See the full secret management guide.

Optional AI tooling

The repository includes a macOS workflow built around Herdr terminal sessions, native agent CLIs, Hermes, and local inference through LM Studio. Treat model and hardware tuning as examples. Each enabled tool still needs its own appropriate authentication and configuration.

Read the AI workflow guide for the project-specific integration and handoff approach.

Activate deliberately

Use the explicit setup target and output name from the getting started guide. VM deployment, libvirt, GPU scripts, and cleanup targets have host-specific effects; inspect their definitions before running them.

Keep a working generation available.

Review changes before activation and retain a known working configuration. make clean also runs Nix garbage collection, so it is not merely a website or build-folder cleanup command.
